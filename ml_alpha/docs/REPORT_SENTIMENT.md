# Report title RPTF / 研报标题情感因子

参考东方证券《因子选股系列研究之八十六：研报文本情感倾向因子》
（文件名日期 2022-12-07，正文日期 2022-12-06），第 6–10 页。
本次只实现用户确认的 **标题版 RPTF**，因子 ID `report_rptf_title`、
券商 tag `DFZQ`。它直接从研报文本学习情感分数，不依赖现有因子列，
也不是用盈利预测调整数值直接当最终因子。

## 1. 本地数据核对

2026-10-20 对 `data/chn_stock_data/analyst_report/2010.parquet` 至
`2026.parquet` 的 17 个文件进行了只读检查：

| 项目 | 本地情况 |
| --- | --- |
| 日期 | 2010-01-01 至 2026-04-30 |
| 原始行数 | 2,852,603；同一报告通常有多个预测年度 |
| 报告事件数 | 按日期、股票、券商、标题去重为 1,206,583，尚未做模型过滤 |
| 标题 | `report_title`，无空值或空白标题；部分标题仅为公司名称 |
| 股票、名称 | `ts_code`、`name` |
| 日期、券商 | `report_date`、`org_name` |
| 预测年度、净利润 | `quarter`（例如 `2026Q4`）、`np`；2,770,885 行 np 非空 |
| 调整幅度 | `imp_dg` 全库为空，不能直接作标签 |
| 摘要、正文 | 本地 schema 和下载器均不包含 |

原报告是朝阳永续数据。本地使用 report_rc，不能宣称逐项复现：

- 原 RPTF 用标题及摘要各 1,000 个高频词；本版只用标题最多 1,000 词。
- RPRF 的完整 318 条手工正则未公开；RPBF 需要同义词词林；
  RPNN 使用腾讯词向量和 GRU。这三支及合成 RPST **不在首版范围**。
- `report_type="非个股"`、空股票/券商/标题不进入事件集。重复预测年度
  不会重复计为多篇报告。作者不用于拆分同一家券商的权重。

## 2. 事件及标签

读取年度 Parquet 的必要列，在内存中整理，不额外派生、落盘或缓存文本表。
以后若接入摘要，可扩展同一事件适配器及模型，保留报告级标签和股票级聚合的分工。

每篇报告选**报告发布当年的 Q4 年度净利润预测**。对同股票、同券商、
同一预测年度，查找严格早于本报告日期的最近一日预测：

```text
y = (np_current - np_previous) / abs(np_previous)
```

只接受两篇报告相距不超过 **12 个自然月**，包含恰好一年前；
不是“同一自然年内”，也不是滚动 252 个交易日。例如 2026-03-01 的
2026Q4 预测可以与 2025-10-01 对 2026Q4 的预测比较，但不能与
2025Q4 的预测比较。使用数据库 `report_date`，不使用回填的 `create_time`。

无历史、前值为零、前后净利润缺失、缺报告当年年度预测的事件不用于训练。
零调整是有效标签，负净利润也按绝对值分母计算。
预测阶段不读 `np/quarter/imp_dg`，不因没有标签而剔除可用标题。

没有可靠的同日日内顺序：同日报告不互作“上一篇”。前一个报告日有多篇且
净利润预测不同，则当前事件标签缺失，不擅自挑一篇或退回更早日期。
同一事件同一预测年度本身存在冲突预测则报错，提示检查数据。

## 3. 文本模型

1. 去掉记录中公司名称、股票代码及控制字符，Jieba 词性分词。
2. 保留报告第 7 页指定的 `d/vn/t/vd/an/ad/v/a/nz/nr/n` 词性。
3. **只在训练集**统计词频，选前 1,000 词；同频按词排序使结果稳定。
4. 特征是 `log(1 + count)`，不采用 TF-IDF。缺词为数值 0，
   使用 float32 稠密矩阵，避免 XGBoost 把稀疏矩阵的缺词解释成缺失值。
5. 标签按训练集平均秩做正态分位变换：
   `Phi^-1((average_rank - 0.5) / N)`。验证集使用保存的训练分布插值，
   不重新排名；超出训练范围夹到训练分位端点。
6. XGBoost 回归器：100 棵树、深度 3、学习率 0.1、平方误差，
   单种子 42、8 CPU 线程、不调参。原文只说默认参数，未给 XGBoost
   版本，本版显式固定参数，避免不同安装版本的默认值变化。

验证集 MSE 只作诊断，不参与词表、标签变换或树参数拟合。
模型输出是变换后情感标签的预测分数，不是百分比收益率，也不限定在 [-1,1]。
清洗分词后为空的标题不训练、不评分，最终覆盖缺失保持空值。

Jieba 固定 `0.42.1`；词典及词性表在内存初始化，绕开其默认系统临时目录
缓存流程，不写 `jieba.cache`，也不写其他文本缓存。实现依据上游
[Tokenizer 源码](https://github.com/fxsjy/jieba/blob/v0.42.1/jieba/__init__.py)。
可选依赖在 `pyproject.toml` 的 `text` extra 中；当前 Python 3.8.3 尚未安装 Jieba。

## 4. 时间和输出

- 沿用公共 `build_windows`：年度重训、回看 36 个月、前 33 个月训练、
  后 3 个月验证。**全部研报事件**参与，不对发布时间每 5 日抽样。
- 没有日内发布时间的报告统一在 `report_date` 后的**下一交易日**可用。
  周末/节假日报告也映射到下一交易日，不会被交易日日历丢掉。
- 标签发布时已知，`lookahead_days=0`；不从未来收益标签库读取数据。
  公共日期边界仍然适用。预测样本的盈利预测字段不会进入模型。
- 每篇报告由其可用日所属年度模型打分，跨年度保留原始样本外评分。
  禁止用新模型重评过去三个月训练样本来补历史。
- 月末在 `(T-3个自然月, T]` 的发布日范围内，选每家券商对每支股票
  最新一日的有效报告分数；同日多篇取均值，再在券商间等权平均。
  无时间衰减、无缺失填充、无额外中性化。只有到 T 已可用的报告参与。
- 月末更新，日度输出持有该月末分数至下一月末；每天再应用股票池、ST、
  BJ 过滤及当日行情股票覆盖。因子日期表示信息可用日，不承诺开盘前可交易。

默认正式输出区间是 **2016-01-01～2026-04-24**。
为恢复首日之前的月末持有值及三个月样本外报告评分，自动增加
**2015 年的预备样本外窗口**，训练配置的 2010 起点能覆盖其训练历史。
因此默认训练产物是 `annual_2015` 至 `annual_2026`。
2015 模型用 2012-01～2014-09 训练、2014-10～2014-12 验证，
2016 模型用 2013-01～2015-09 训练、2015-10～2015-12 验证，
实际样本边界由公共交易日窗口及下一交易日可用规则确定。

缩小预测日期范围时仍回放必要的上一年度事件和月末状态，要求相应旧模型存在；
不会以新模型替代缺失的旧模型。首个样本外窗口若还不足完整三个月，聚合先为空。
月底判断使用完整交易日历，不把一个截断的预测区间末日误当月末。

| 产物 | 路径 |
| --- | --- |
| 配置 | `ml_alpha/factors/report_rptf_title.toml` |
| 模型、词表、训练标签分布 | `data/model_workspace/report_rptf_title/artifacts/annual_<year>/model.pkl` |
| 公共兼容性清单 | 同目录 `model.manifest.json` |
| 可读词表、MSE诊断 | 同目录 `vocabulary.json`、`model_info.json` |
| 正式单列因子 | `data/factors/stock/daily/<year>/<date>_ml.parquet` 中 `report_rptf_title` |

配置、特征或数据版本变化时，公共 manifest 要求重训。
新增或修订历史源数据应更新配置 `data_version`，不要复用旧模型冒充新数据训练。
文本模型会在加载时核对 Jieba 版本。

## 5. 资源和 CLI

不新增派生数据集，不写样本矩阵缓存。年度文件只投影必要列；
训练/验证分别读取需要的窗口和一年的标签比较历史。
每个预测年度只读一次投影后的事件，再按日期批次评分/写出，
三个月评分簿仅保存在内存。Jieba 的字典在进程内复用。

训练稠密输入大小是 `有效训练报告数 × 实际词数 × 4 bytes`：
例如 10 万篇 × 1,000 词约 **381 MiB**，20 万篇约 **763 MiB**；
这是矩阵本体估算，不含文本、分词、XGBoost 内部矩阵及树训练工作内存。
训练日志打印实际矩阵 MiB。验证和预测每 4,096 篇构建一块矩阵，
1,000 词时约 15.6 MiB；该参数是模型的 `prediction_batch_size`，
与公共 `materialize.predict_batch_size=20`（交易日期数）不同。

首次运行前需要安装可选依赖，以下命令仅供手动执行，本轮未安装或运行。
如果只缺 Jieba，可单独安装它；把 pip 临时路径也设置到项目 D 盘：

```powershell
Set-Location D:\yuminwu_workspace\Internship\YuminQuant
$py = "D:\Users\Devin\anaconda383\python.exe"
$env:PYTHONPATH = "$PWD\ml_alpha"
$env:PATH = "D:\Users\Devin\anaconda383;D:\Users\Devin\anaconda383\Library\bin;D:\Users\Devin\anaconda383\Scripts;" + $env:PATH

# 安装时的临时目录，非模型缓存。安装完成后可自行清理。
$pipTemp = Join-Path $PWD "tmp\pip"
New-Item -ItemType Directory -Force -Path $pipTemp | Out-Null
$env:TEMP = $pipTemp
$env:TMP = $pipTemp
& $py -B -m pip install --no-cache-dir "jieba==0.42.1"

& $py -B -u -m yq_ml_alpha factor-train `
  --config ml_alpha\factors\report_rptf_title.toml

& $py -B -u -m yq_ml_alpha factor-predict `
  --config ml_alpha\factors\report_rptf_title.toml

# 训练+预测合并命令（与上面二选一）
& $py -B -u -m yq_ml_alpha factor-run `
  --config ml_alpha\factors\report_rptf_title.toml
```

沿用 `factor-train / factor-run --resume` 的模型清单核对。
`factor-run --resume` 会复用模型并重新回放事件、写出请求日期，避免恢复时
丢失月度状态；不会只跳过某个已有输出的年度。无需派生 CLI 或生成未来收益标签。
`factor-materialize` 对此输入明确报不支持，防止误落盘或调用数值因子预处理器。

本轮只做源数据只读核对和代码实现，未启动测试、训练、预测或回测。
