# Analyst Consensus Derived Data / 一致预期派生数据说明

This document describes the daily wide analyst-consensus dataset generated by
`derive-consensus`.

本文说明 `derive-consensus` 生成的日频宽表一致预期数据，供后续因子开发、
数据检查和增量维护使用。

## Output / 输出位置

Output path:

```text
data/derived/stock/consensus/{trade_date}.parquet
```

输出路径：

```text
data/derived/stock/consensus/{trade_date}.parquet
```

Each file is one trading day. Each row is one stock. The table is intentionally
wide: only final consensus metric columns are written. Helper columns such as
`*_type`, `*_inst_count`, and `*_hisdate` are not output.

每个文件对应一个交易日，每行对应一只股票。当前采用宽表格式，只输出最终一致
预期指标值，不输出 `*_type`、`*_inst_count`、`*_hisdate` 等辅助状态列。

## CLI / 生成命令

Full history example:

```powershell
cargo run --release --manifest-path factor_engine\Cargo.toml -- derive-consensus `
  --start-date 20110101 `
  --end-date 20260424 `
  --date-batch-size 120 `
  --overwrite true
```

全量历史生成示例：

```powershell
cargo run --release --manifest-path factor_engine\Cargo.toml -- derive-consensus `
  --start-date 20110101 `
  --end-date 20260424 `
  --date-batch-size 120 `
  --overwrite true
```

Notes / 说明：

- `--overwrite true` overwrites existing daily parquet files. It is the default.
- `--overwrite false` skips existing daily files.
- `--date-batch-size` controls sequential processing batches. Progress is still
  reported by output trading date because one parquet file is written per date.
- `--overwrite true` 会覆盖已有日文件，且为默认值。
- `--overwrite false` 会跳过已有日文件。
- `--date-batch-size` 控制顺序处理批次；进度条仍按输出日期推进，因为每天
  写一个 parquet。

## Selective Regeneration / 按列重生成

`derive-consensus --columns name1,name2` computes only requested outputs and their
dependencies. All existing consensus metric names listed below are supported;
unknown names, key columns and empty selections are rejected. Omitting `--columns`
preserves the full-table generation behavior.

新增 `--columns`，支持下文全部一致预期指标列名，以逗号分隔。不传该参数仍为原来的
全量生成。未知字段、键列和空选择会报错。重复字段自动去重，不支持通配符。

Only regenerate the ten CAGR/PEG fields / 仅重生成十个 CAGR/PEG 字段：

```powershell
$columns = foreach ($suffix in @("fy0", "fy1", "fy2", "fy3", "roll")) {
  "con_npcgrate_2y_$suffix"
  "con_peg_$suffix"
}
cargo run --release --manifest-path factor_engine\Cargo.toml -- derive-consensus `
  --start-date 20160101 `
  --end-date 20260424 `
  --columns ($columns -join ",") `
  --date-batch-size 120 `
  --overwrite true
```

- Partial writes align by `(trade_date, ts_code)`, replacing selected columns,
  including explicit nulls. Other columns keep their values and types. The stock
  universe is the union of old and new rows; selected values for old-only rows are
  cleared, and unselected values for new-only rows are null.
- 按 `(trade_date, ts_code)` 对齐，选中列的新空值也覆盖旧值。未选中列保持原值和类型。
  股票取新旧行并集：仅旧表存在的股票，其选中列清空；新增股票的未选中列为空。
  若整日输入股票网格为空且旧表非空，则报错保护旧文件，避免缺整日源数据导致整列误清空。
- If the file is absent, only keys and requested columns are created. With
  `--overwrite false`, an existing file is skipped entirely, even if it lacks a
  requested column. Dependencies are computed but not implicitly written; request
  PEG explicitly when refreshing CAGR if PEG must also be updated.
- 文件不存在时仅创建键列和指定列；`--overwrite false` 仍按文件跳过，不补写缺失列。
  依赖只在内存中计算，不隐式改写未请求列；修正 CAGR 后需要同时请求 PEG 才会更新 PEG。
- Input columns and computational branches are selected by dependencies. CAGR-only
  requests do not load balance sheets, EPS, price values, revenue, ratings, targets,
  or revision history. PEG adds EPS and prices. Forecast/PIT state remains shared
  across date batches; the original daily PV key universe is unchanged.
- 按依赖裁剪输入和计算分支。只算 CAGR 时不加载资产负债表、EPS、价格值、收入、评级、
  目标价和预测修正率历史；PEG 额外加载 EPS 和价格。复用跨 batch 预测/PIT 缓存。
  派生宽表原有的日频 PV 股票键网格保持不变，没有将其改为财务因子的 panel。
- Parquet still requires a daily-file rewrite: keep only one old daily table in
  memory, merge column-wise, write Snappy to a same-directory temporary file and
  replace the original after completion. Do not run concurrent writers on the same
  target dates. No whole-history wide table or per-cell string map is built.
- Parquet 不能原地替换列：仍需重写单日文件，但只读取一个旧日表，逐列合并后以 Snappy
  写同目录临时文件，完成后替换原文件。不构建全历史宽表或逐单元格字符串映射。
  不要对相同目标日期并发运行多个写入任务。

## Rows And Columns / 行与列

Base columns / 基础列：

- `trade_date`
- `ts_code`

Annual suffixes / 年度后缀：

- `fy0`
- `fy1`
- `fy2`
- `fy3`

The fiscal-year anchor is stock-specific. Before May 1, advance as soon as
that stock's previous-calendar-year annual income statement is PIT-visible.
From May 1 onward, advance unconditionally, even if that annual report is absent.

```text
Y = trade_date year
annual_visible = a PIT-visible annual income record exists for (Y-1)-12-31
fy0 = Y-1 if month-day >= 0501 or annual_visible else Y-2
fy1 = fy0 + 1
fy2 = fy0 + 2
fy3 = fy0 + 3
```

财年锚点按股票确定：五月一日前，上一年度正式年报已经 PIT 可见则提前切换；
未披露则保持旧基准年。五月一日起，不论披露与否统一切换。
披露判断采用与实际值相同的利润表 PIT reader、合并报表优先级及
`f_ann_date.or(ann_date) <= trade_date`，即公告日期当天生效，不额外延迟一天。
只判断上一年度 12 月 31 日记录是否存在，不要求利润、收入或 EPS 非空；
季报、业绩预告和快报不触发切换。五月一日后 FY0 仍可能是预测值。

### Fiscal-anchor migration / 财年锚点历史迁移

This replaces the old market-wide May 1-only switch. Regenerate all 48 annual
columns (12 families times four FY suffixes), plus five `con_npgrate_*` columns.
The 12 calendar-year rolling columns, ratings and targets are unchanged.
Annual differences occur between each early disclosure and April 30; revision
differences can persist for up to 364 days because historical FY0 values change.
Revision metrics still compare each date's own FY0, not a fixed target year.

旧数据不会自动迁移。需重生成 48 个年度字段及 5 个变化率字段，共 53 列。
变化率仍比较两个时点各自的 FY0，切换时可能包含跨财年增长，未改为同财年预测修正。
不能只更新每年的一至四月，变化率受历史比较值影响可延续到之后约一年。
当前直接受影响的下游因子为 `equity_duration`，需在派生数据更新后重新生产；
`bet_cagr_csv_std` 和 HAZQ 可比估值的一致预期依赖均为滚动列，不受此变更影响。

Run from the repository root. Set the range to the history being maintained;
the example covers the existing local consensus files through 2026-04-24.
The generator loads its own warmup history. These commands do not download raw data.

在仓库根目录依次执行；以下日期覆盖现有本地一致预期历史。派生引擎自动加载预热历史，
但原始数据必须已具备所需覆盖范围。因子生产会替换选中列，保留其他因子列。

```powershell
$startDate = '20110101'
$endDate = '20260424'
$families = @(
  'con_or', 'con_np', 'con_eps', 'con_na', 'con_pb', 'con_ps',
  'con_pe', 'con_peg', 'con_roe', 'con_or_yoy', 'con_np_yoy', 'con_npcgrate_2y'
)
$columns = @(foreach ($family in $families) {
  foreach ($suffix in @('fy0', 'fy1', 'fy2', 'fy3')) { "${family}_${suffix}" }
})
$columns += @('con_npgrate_1w', 'con_npgrate_4w', 'con_npgrate_13w', 'con_npgrate_26w', 'con_npgrate_52w')

cargo run --release --manifest-path factor_engine/Cargo.toml -- derive-consensus `
  --start-date $startDate --end-date $endDate `
  --columns ($columns -join ',') --date-batch-size 120 --overwrite true
if ($LASTEXITCODE -ne 0) { throw 'Consensus regeneration failed; do not rebuild factors yet.' }

cargo run --release --manifest-path factor_engine/Cargo.toml -- run `
  --asset stock --frequency daily --start-date $startDate --end-date $endDate `
  --factors equity_duration --date-batch-size 120 --profile
if ($LASTEXITCODE -ne 0) { throw 'Equity duration regeneration failed.' }
```

## Annual Metrics / 年度指标

### Units / 单位约定

All derived monetary totals use **wan yuan (10,000 CNY)**: `con_or_*`, `con_np_*`
and `con_na_*`. Raw analyst `op_rt`/`np` forecasts are already in wan yuan and are
not rescaled. PIT income `revenue`/`n_income_attr_p` and balance-sheet equity are
in yuan and are divided by 10,000 at the consensus boundary. The original files
and the shared PIT readers are unchanged. EPS and prices remain yuan per share;
`con_np / con_eps` consequently represents shares in units of 10,000. Growth and
ROE outputs remain percentages; PE/PB/PS/PEG are ratios.

金额统一为**万元**：分析师原始 `op_rt/np` 不换算；财报实际收入、归母净利润和归母权益
仅在一致预期派生层除以 10000。EPS 与价格仍为元/股，隐含股本 `con_np/con_eps` 为万股，
增长率和 ROE 仍为百分数。下载文件、共用 PIT reader 及其他财报因子的单位不变。

Older derived files mixed yuan actuals with wan-yuan forecasts. They must be
regenerated before combining with new files. Rebuild the following families for
all `fy0/fy1/fy2/fy3/roll` suffixes: `con_or`, `con_np`, `con_na`, `con_pb`, `con_ps`,
`con_roe`, `con_or_yoy`, `con_np_yoy`, `con_npcgrate_2y`, `con_peg`; also rebuild
`con_npgrate_1w/4w/13w/26w/52w`. This is 55 columns. EPS, PE, ratings and targets
do not require regeneration for this unit correction. No files are migrated
automatically. Ensure the rebuilt range also covers downstream factor warmup.

历史文件存在元/万元混用，需重生成上述 55 列，且覆盖下游滚动因子的 warmup 日期。
不自动迁移数据，不应把未重生成的旧金额列与新列混用。EPS、PE、评级和目标价不受本次
单位修正影响。只重生成 CAGR/PEG 十列不足以完成这次单位迁移。

The following annual metrics are output for every suffix `fy0..fy3`.

以下指标均输出 `fy0..fy3` 四个版本。

### `con_or_fy*`

Consensus operating revenue.

一致预期营业收入。

Construction / 合成口径：

- If actual annual financial revenue is PIT-visible, use actual `revenue`.
- Otherwise use analyst forecasts from `op_rt`.
- Forecast rows use only annual forecasts where `quarter = YYYYQ4`.
- Analyst abnormal values such as `NaN`, `inf`, and `-inf` are dropped before
  aggregation.

- 如果年度真实财报营业收入已 PIT 可见，使用真实 `revenue`。
- 否则使用分析师明细 `op_rt`。
- 只使用 `quarter = YYYYQ4` 的年度预测。
- 分析师明细中的 `NaN`、`inf`、`-inf` 等异常值会先剔除。

### `con_np_fy*`

Consensus net profit attributable to parent.

一致预期归母净利润。

Construction / 合成口径：

- If actual annual financial net profit is PIT-visible, use actual
  `n_income_attr_p`.
- Otherwise use analyst forecasts from `np`.
- Forecast rows use only annual forecasts where `quarter = YYYYQ4`.

- 如果年度真实归母净利润已 PIT 可见，使用真实 `n_income_attr_p`。
- 否则使用分析师明细 `np`。
- 只使用 `quarter = YYYYQ4` 的年度预测。

### `con_eps_fy*`

Consensus EPS.

一致预期 EPS。

Construction / 合成口径：

- If actual annual financial EPS is PIT-visible, use actual `basic_eps`.
- Otherwise use analyst forecasts from `eps`.
- Forecast rows use only annual forecasts where `quarter = YYYYQ4`.

- 如果年度真实 EPS 已 PIT 可见，使用真实 `basic_eps`。
- 否则使用分析师明细 `eps`。
- 只使用 `quarter = YYYYQ4` 的年度预测。

### Annual Forecast Aggregation / 年度预测聚合

For `con_or`, `con_np`, and `con_eps`, the generator uses the following
stateful forecast rules:

`con_or`、`con_np`、`con_eps` 的分析师预测聚合采用以下状态机规则：

- Keep the latest valid forecast per `ts_code + fiscal_year + metric + org_name`.
- Strict window: forecasts in the past 90 natural days. If there are at least
  6 institutions, use equal-weight aggregation.
- Loose window: if strict samples are insufficient, use available forecasts in
  the past 120 natural days.
- Carry window: if no loose forecast exists, carry available forecasts in the
  past 183 natural days.
- If no forecast is available, output null.
- 每个 `股票 + 财年 + 指标 + 机构` 只保留最新有效预测。
- 严格窗口：过去 90 个自然日内预测，机构数至少 6 家时等权聚合。
- 宽松窗口：严格样本不足时，使用过去 120 个自然日内可用预测。
- 沿用窗口：如果 120 日内没有可用预测，沿用过去 183 个自然日内可用预测。
- 完全没有可用预测时输出空值。

The original document mentions institution/time influence weights but does not
provide the exact weighting function. The current implementation uses
deterministic equal weighting and keeps the aggregation point replaceable in
code.

原始文档提到机构影响力和发布时间影响力，但没有给出具体权重函数。当前实现
使用确定性的等权聚合，并保留后续替换权重模型的代码位置。

### `con_na_fy*`

Consensus net assets.

一致预期净资产。

Formula / 公式：

```text
con_na = latest PIT visible total_hldr_eqy_exc_min_int / 10000 + 0 + con_np
```

Notes / 说明：

- Fundraising amount is not available locally and is treated as `0`.
- `total_hldr_eqy_exc_min_int <= 0` is invalid and makes `con_na` null.
- 募集资金本地无数据，按 `0` 处理。
- `total_hldr_eqy_exc_min_int <= 0` 时 `con_na` 为空。

### `con_pb_fy*`

Consensus PB.

一致预期市净率。

Formula / 公式：

```text
shares = con_np / con_eps
con_pb = close_price * shares / con_na
```

`close_price` uses `close`; if `close <= 0` or missing, it falls back to
`pre_close`.

`close_price` 优先使用 `close`；若 `close <= 0` 或缺失，则使用 `pre_close`。

### `con_ps_fy*`

Consensus PS.

一致预期市销率。

Formula / 公式：

```text
shares = con_np / con_eps
con_ps = close_price * shares / con_or
```

### `con_pe_fy*`

Consensus PE.

一致预期市盈率。

Formula / 公式：

```text
con_pe = close_price / con_eps
```

### `con_roe_fy*`

Consensus ROE.

一致预期净资产收益率。

Formula / 公式：

```text
con_roe = 100 * con_np / con_na
```

### `con_or_yoy_fy*`

Consensus operating revenue year-on-year growth.

一致预期营业收入同比。

Formula / 公式：

```text
con_or_yoy = 100 * (con_or_t - con_or_{t-1}) / abs(con_or_{t-1})
```

### `con_np_yoy_fy*`

Consensus net profit year-on-year growth.

一致预期净利润同比。

Formula / 公式：

```text
con_np_yoy = 100 * (con_np_t - con_np_{t-1}) / abs(con_np_{t-1})
```

### `con_npcgrate_2y_fy*`

Consensus two-year net-profit growth transform.

一致预期两年净利润增长变换。

The current project convention is user-adjusted from the original document:
use the profit ratio with an absolute base-profit denominator inside the square
root, not the difference in profits. Negative base profit is allowed.

当前项目口径采用用户确认调整：平方根内部使用利润比值，基期利润取绝对值，
不先计算利润差。允许基期利润为负。

Formula / 公式：

```text
base_np = con_np_{fyX-2}
current_np = con_np_{fyX}
profit_ratio = current_np / abs(base_np)

con_npcgrate_2y_fyX = 100 * (sqrt(profit_ratio) - 1)
```

Null rules / 空值规则：

- `base_np` missing or `abs(base_np) <= eps`: null
- `current_np` missing: null
- `current_np < 0`, non-finite inputs, ratio or result: null

- `base_np` 缺失或 `abs(base_np) <= eps`：空
- `current_np` 缺失：空
- `current_np < 0`，输入、比值或结果非有限：空

A zero current profit gives -100%; declining positive profit produces a negative
growth rate. These growth values are retained, while PEG still requires positive
growth. This absolute-base convention is not standard CAGR for a loss-making base.

当期利润为 0 时返回 -100%；正利润下降时保留负增长率。PEG 仍要求增长率为正。
亏损基期取绝对值是本项目约定，不等同于亏损情形下的标准 CAGR。

### `con_peg_fy*`

Consensus PEG.

一致预期 PEG。

Formula / 公式：

```text
con_peg = con_pe / con_npcgrate_2y
```

Null rules / 空值规则：

- `con_pe < 0`: null
- `con_npcgrate_2y <= 0`: null
- any input missing: null

- `con_pe < 0`：空
- `con_npcgrate_2y <= 0`：空
- 任一输入缺失：空

## Rolling Metrics / 滚动指标

Rolling metrics use calendar-year interpolation:

滚动指标采用自然年插值：

```text
w = days_until_year_end(trade_date) / 365
current_roll = value_current_calendar_year * w
             + value_next_calendar_year * (1 - w)

historical_roll = value_previous_calendar_year * w
                + value_current_calendar_year * (1 - w)
```

Output rolling columns / 输出滚动列：

- `con_or_roll`
- `con_np_roll`
- `con_eps_roll`
- `con_na_roll`
- `con_pb_roll`
- `con_ps_roll`
- `con_pe_roll`
- `con_peg_roll`
- `con_roe_roll`
- `con_or_yoy_roll`
- `con_np_yoy_roll`
- `con_npcgrate_2y_roll`

### Rolling Valuation / 滚动估值

```text
con_pe_roll = close_price / con_eps_roll
shares_roll = con_np_roll / con_eps_roll
con_pb_roll = close_price * shares_roll / con_na_roll
con_ps_roll = close_price * shares_roll / con_or_roll
con_roe_roll = 100 * con_np_roll / con_na_roll
```

### Rolling YoY / 滚动同比

```text
con_or_yoy_roll = 100 * (con_or_roll - historical_or_roll) / abs(historical_or_roll)
con_np_yoy_roll = 100 * (con_np_roll - historical_np_roll) / abs(historical_np_roll)
```

### `con_npcgrate_2y_roll`

Rolling net-profit growth transform.

滚动净利润增长变换。

Formula / 公式：

```text
future_roll_np =
    con_np_calendar_year * w
  + con_np_next_calendar_year * (1 - w)

historical_roll_np =
    con_np_{calendar_year-2} * w
  + con_np_{calendar_year-1} * (1 - w)

profit_ratio = future_roll_np / abs(historical_roll_np)

con_npcgrate_2y_roll = 100 * (sqrt(profit_ratio) - 1)
```

Null rules are the same as annual `con_npcgrate_2y_fy*`.

空值规则同年度 `con_npcgrate_2y_fy*`。

Combine the annual profits first, then take the absolute value of the historical
combination and calculate the ratio. Do not average annual growth rates or replace
the rolling combination with a fixed fy2/fy0 ratio. Existing annual source selection
(PIT actuals first, forecasts otherwise) is unchanged.

先分别组合年度利润，再对历史组合利润取绝对值并计算比值；不对年度增长率取平均，
也不使用固定 fy2/fy0 比值代替滚动组合。年度取数规则保持不变：优先 PIT 实际值，
否则使用预测值。本次公式更新不自动重写已有派生数据或因子文件。

### `con_peg_roll`

Rolling PEG.

滚动 PEG。

Formula / 公式：

```text
con_peg_roll = con_pe_roll / con_npcgrate_2y_roll
```

Null rules / 空值规则：

- `con_pe_roll < 0`: null
- `con_npcgrate_2y_roll <= 0`: null
- any input missing: null

- `con_pe_roll < 0`：空
- `con_npcgrate_2y_roll <= 0`：空
- 任一输入缺失：空

## Forecast Revision Metrics / 预测变化率

Output columns / 输出列：

- `con_npgrate_1w`
- `con_npgrate_4w`
- `con_npgrate_13w`
- `con_npgrate_26w`
- `con_npgrate_52w`

Formula / 公式：

```text
con_npgrate_X =
    100 * (current_con_np_fy0 - previous_con_np_fy0)
        / abs(previous_con_np_fy0)
```

Anchor dates use natural-day offsets and then map to the latest open trading day
on or before the anchor:

锚点使用自然日偏移，并映射到该自然日前最近一个开市交易日：

```text
1w  = 7 natural days
4w  = 28 natural days
13w = 91 natural days
26w = 182 natural days
52w = 364 natural days
```

## Rating And Target Price / 评级与目标价

### `con_rating_strength`

Consensus rating strength.

一致预期评级强度。

Mapping / 映射：

```text
买入 / 强烈推荐 / 推荐 / buy / strong buy        -> 1.00
增持 / 优于大市 / 跑赢行业 / outperform / overweight -> 0.75
中性 / 持有 / 无 / neutral / hold                 -> 0.50
减持 / 低于大市 / underperform / underweight       -> 0.25
卖出 / sell                                      -> 0.00
```

Aggregation / 聚合：

- Keep the latest valid rating per `ts_code + org_name`.
- Use ratings in the past 90 natural days.
- Output equal-weight mean of mapped strengths.
- 每个 `股票 + 机构` 保留最新有效评级。
- 使用过去 90 个自然日内评级。
- 输出映射强度的等权均值。

### `con_target_price`

Consensus target price.

一致预期目标价。

Aggregation / 聚合：

- Keep the latest valid `min_price` per `ts_code + org_name`.
- Use target prices in the past 90 natural days.
- Output equal-weight mean.
- 每个 `股票 + 机构` 保留最新有效 `min_price`。
- 使用过去 90 个自然日内目标价。
- 输出等权均值。

## State, PIT, And Performance / 状态机、PIT 与性能

`derive-consensus` is a derived-data generator, not a normal factor provider.
It uses a cross-batch state machine:

`derive-consensus` 是派生数据生成器，不是普通因子 provider。它使用跨 batch
状态机：

- The first batch warms up analyst reports from `start_date - 600 natural days`.
- Later batches only ingest newly visible analyst reports.
- Forecast/rating/target states are pruned to their effective windows.
- `con_np_fy0` history is retained for the revision metrics.
- Annual base snapshots are cached by `ts_code + fiscal_year` and recomputed
  only when analyst reports, PIT financial records, or forecast window expiry
  require it.

- 第一批从 `start_date - 600` 个自然日开始 warmup。
- 后续 batch 只增量 ingest 新出现的分析师明细。
- 预测、评级、目标价状态只保留有效窗口。
- `con_np_fy0` 历史用于计算预测变化率。
- 年度基础 snapshot 按 `股票 + 财年` 缓存，仅在分析师明细、PIT 财报记录或窗口
  过期导致状态变化时重算。

Daily market columns and final valuation columns are still computed on each
output trading day, because price can change daily.

日频价格和最终估值类列每天计算，因为价格是日频快变量。
