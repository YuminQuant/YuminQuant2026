# YuminQuant Factor Engine

This crate is the Rust factor engine for the YuminQuant local parquet data lake.
It computes ordinary factors, minute-to-daily factors, Barra CNE6 exposures, and
future-return labels without moving data out of the local workspace.

## What It Produces

```text
data/factors/{asset}/{frequency}/{year}/{trade_date}.parquet
data/factors/_cache/intraday_daily/chn_stock/{year}/{trade_date}.parquet
data/barra/{asset}/daily/CNE6/{year}/{trade_date}.parquet
data/label/{asset}/{frequency}/{year}/{trade_date}.parquet
```

Each daily output file is wide: key columns plus one column per factor, Barra
exposure, or label. If a file already exists, the writer merges or overwrites the
selected columns and keeps unrelated existing columns.

## Source Layout

```text
src/
  factor/
    chn_stock/
      daily/              # one ordinary stock daily factor per .rs file
      minute/             # true minute-frequency factors
    future/
      daily/
      minute/
    common/               # panel views and shared factor-development utilities
    registry.rs           # generated by build.rs
  barra/
    chn_stock/daily/cne6/ # one Barra family per .rs file
  label/
    chn_stock/daily/      # one label per .rs file
  operators/
    time_series/          # ts_mean, ts_std_dev, ts_corr, ...
    cross_sectional/      # cs_rank, cs_neutralize, cs_scale, ...
```

Concrete factor logic belongs in its own factor file. `common` is for reusable
data views and wiring, while `operators` is for reusable math.

## Core Commands

From the repository root:

```powershell
cargo run --release --manifest-path factor_engine\Cargo.toml -- metadata
cargo run --release --manifest-path factor_engine\Cargo.toml -- list --asset stock --frequency daily
cargo run --release --manifest-path factor_engine\Cargo.toml -- plan --asset stock --frequency daily --start-date 20260424 --end-date 20260424
cargo run --release --manifest-path factor_engine\Cargo.toml -- run --asset stock --frequency daily --start-date 20260424 --end-date 20260424 --profile
```

Run selected factors:

```powershell
cargo run --release --manifest-path factor_engine\Cargo.toml -- run --asset stock --frequency daily --start-date 20260424 --end-date 20260424 --factors WQAlpha009
cargo run --release --manifest-path factor_engine\Cargo.toml -- run --asset stock --frequency daily --start-date 20260424 --end-date 20260424 --tags worldquant101alpha --factor-batch-size 10 --profile
```

Barra and label workflows:

```powershell
cargo run --release --manifest-path factor_engine\Cargo.toml -- barra-metadata
cargo run --release --manifest-path factor_engine\Cargo.toml -- barra-run --asset stock --frequency daily --start-date 20260424 --end-date 20260424 --families size,volatility --profile

cargo run --release --manifest-path factor_engine\Cargo.toml -- label-metadata
cargo run --release --manifest-path factor_engine\Cargo.toml -- label-run --asset stock --frequency daily --start-date 20260101 --end-date 20260130 --profile
```

Cross-sectional backtest workflows:

```powershell
cargo run --release --manifest-path factor_engine\Cargo.toml -- backtest --asset stock --frequency daily --start-date 20110101 --end-date 20260424 --factors utd --groups 10 --rebalance 5
cargo run --release --manifest-path factor_engine\Cargo.toml -- backtest --asset stock --frequency daily --start-date 20110101 --end-date 20260424 --tags XYZQ --groups 10 --rebalance weekly --factor-batch-size 10
cargo run --release --manifest-path factor_engine\Cargo.toml -- backtest --asset stock --frequency daily --start-date 20110101 --end-date 20260424 --all-factors --groups 10 --rebalance 5 --factor-batch-size 10 --date-batch-size 120 --threads 8
```

Backtest outputs are written as one parquet per factor:

```text
data/backtest/stock/daily/returns/{factor_id}.parquet
data/backtest/stock/daily/ic/{factor_id}.parquet
data/backtest/stock/daily/factor_stats/{factor_id}.parquet
```

Useful flags:

- `--factor-batch-size N`: number of factors computed together, default `64`.
- `--threads N`: rayon worker count for factor-level parallelism.
- `--profile`: print load, compute, write timings plus row and non-null counts.
- `--refresh-minute-cache`: rebuild minute-to-daily raw cache.
- Backtest also supports `--factor-batch-size N`, default `10`, and loads only
  that many factor columns per batch. Backtest `--date-batch-size N` defaults
  to `120` and limits how many factor dates are held in memory at once. Each
  factor batch is computed in parallel with rayon; use `--threads N` to cap
  worker count.

## Execution Model

The ordinary factor engine aligns requested dates to the trading calendar, then
executes by date batch and factor batch. The default date batch size is `1`, so a
long run loops trading day by trading day. Within each date, factors are chunked
by `--factor-batch-size`; the factors in one batch are computed in parallel by
rayon.

For each execution batch:

1. The engine merges the selected factors' declared `DataRequest`s.
2. It computes exact `load_dates` from target dates and each factor's lookback.
3. Loaders read only those daily parquet files, not whole years, when daily files
   are available.
4. `DataPool` eagerly builds and caches `DailyPanel`s once per dataset.
5. Factor `compute()` functions reuse the cached panels.
6. Results are written immediately to per-date wide parquet files.
7. The batch `DataPool`, panels, and results are released.

Minute-to-daily factors use a two-step design. `minute_compute()` materializes a
single-day raw statistic into `_cache/intraday_daily`; the ordinary `compute()`
then reads that raw daily panel and applies daily post-processing such as
`ts_mean`, `cs_neutralize`, or Barra neutralization.

Labels are stricter than factors: if the maximum lookahead is unavailable, that
target date is skipped and no label file is written. Factors with insufficient
history usually still write rows with `null` values.
